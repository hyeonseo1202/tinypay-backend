# Payment reconciliation

내부 `PaymentLog`와 블록체인 영수증을 주기적으로 비교해 거래 상태, 공식 토큰 컨트랙트,
수신자 및 금액 불일치를 탐지한다.

## 처리 흐름

1. 스케줄러가 미대사 및 재시도 대상 결제를 조회한다.
2. DB 비관적 락으로 대상 행을 선점하고 `PROCESSING`으로 변경한다.
3. 블록체인 영수증의 거래 상태, 컨트랙트, 수신자, 금액을 검증한다.
4. 일치하면 `MATCHED`, 불일치하면 `MISMATCHED`로 기록한다.
5. RPC 등 일시적 외부 오류는 `RETRY_REQUIRED`로 변경하고 다음 실행 시각을 저장한다.
6. 최대 재시도 횟수를 초과하면 `RETRY_EXHAUSTED`로 남겨 수동 확인 대상으로 분리한다.

최초 결제 검증의 replay 방지 로직은 영수증을 Redis에 사용 처리한다. 대사에서는 이미
사용된 정상 영수증을 다시 확인해야 하므로 replay 검사와 Redis 등록을 생략하고 온체인
정보만 검증한다.

## 중복 배치 방지

대상 조회 시 `PESSIMISTIC_WRITE` 행 잠금을 사용하고 같은 트랜잭션에서 `PROCESSING`으로
변경한다. 여러 애플리케이션 인스턴스가 동시에 스케줄러를 실행해도 한 결제는 한 인스턴스만
선점한다.

프로세스가 선점 후 종료되는 경우를 위해 일정 시간 이상 `PROCESSING`인 건을
`RETRY_REQUIRED`로 복구한다.

## 결과 기록

`PaymentLog`에는 현재 대사 상태, 시도 횟수, 시작·완료 시각, 다음 재시도 시각 및 마지막
오류를 저장한다. 각 확정 검증 결과는 `TxVerificationLog`에 별도로 추가해 대사 이력을
보존한다.

현재 검증기는 실제 수신자와 실제 금액을 결과 객체로 반환하지 않으므로 상세 문자열과
실패 단계만 기록한다. 추후 `VerificationResult`에 실제 온체인 값을 구조화하면
`actualReceiver`와 `actualAmount`도 채울 수 있다.
